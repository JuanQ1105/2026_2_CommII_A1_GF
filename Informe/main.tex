\begin{abstract}
 This report presents the development and implementation of custom Python blocks within the GNU Radio environment, designed for Software-Defined Radio (SDR) applications. Various digital signal processing algorithms were implemented using a collaborative workflow and version control via Git and GitHub. These include accumulator and differentiator blocks, as well as modules for calculating statistical metrics in real time.  The
system’s performance was evaluated under variable sam
pling rates and noisy environments, validating theoretical digital communication models. Results demonstrate the efficiency of programmable blocks for signal characterization and robust experimentation in SDR platforms.
\end{abstract}

\begin{IEEEkeywords}
SDR, GNU Radio, Python, Signal Processing,
Accumulator, Differentiator
\end{IEEEkeywords}

\section{Introducción}

 La radio definida por software (SDR) es un sistema de radiocomunicaciones donde la mayoría de las funciones de radio se implementan mediante software en lugar de hardware dedicado, permitiendo flexibilidad y reconfiguración dinámica. Herramientas como GNU Radio facilitan la creación y evaluación de sistemas digitales mediante diagramas de flujo que ilustran etapas esenciales en el procesamiento de señales.
 GNU Radio constituye el marco de trabajo estándar para este propósito; no obstante, la construcción de sistemas avanzados exige trascender el uso de bloques predeterminados mediante la programación de módulos a la medida. Este informe aborda el desarrollo e integración de bloques nativos en Python para procesar flujos de datos en tiempo real.  Para estructurar la solución, se codificaron algoritmos de acumulación y diferenciación discreta, seguidos por un bloque de estimación estadística orientado a caracterizar señales dinámicas. Dichos módulos se integraron en una aplicación práctica diseñada para la mitigación y análisis de ruido, demostrando la utilidad de los descriptores estadísticos en el filtrado y detección de señales. Adicionalmente, el proceso de desarrollo e integración del código se coordinó de forma distribuida utilizando un flujo de trabajo basado en ramas en Git y GitHub.

\section{Metodología}

El desarrollo de esta práctica se centró en el diseño, implementación y validación de tres algoritmos utilizando la herramienta GNU Radio Companion. El flujo de trabajo se dividió en tres fases principales correspondientes a cada bloque procesador: un acumulador, un diferenciador y un analizador estadístico.
\begin{itemize}
    \item Diseño del Bloque Acumulador: El primer algoritmo consistió en la implementación de un sistema acumulador discreto, cuya función matemática responde a la ecuación: $y[n]=y[n-1]+x[n]$.
    \item Diseño del Bloque Diferenciador: El segundo algoritmo implementó un diferenciador discreto de primer orden, modelado mediante la ecuación $y[n]=x[n]-x[n-1]$.
    \item Implementación del Analizador Estadístico: El tercer algoritmo implementa el cálculo de métricas estadísticas en tiempo real (Media, Media Cuadrática, Valor RMS, Potencia Promedio y Desviación Estándar).
    Los codigos del bloque de python de cada uno de los algoritmos se extrajeron del libro guia\cite{b1}.
\end{itemize}



\section{RESULTADOS Y ANÁLISIS DE DATOS}

\subsection{Bloque Acumulador}
Para analizar el comportamiento del bloque acumu
lador en GNU Radio, se implementó un diagrama de
flujo compuesto por un bloque Vector Source, un bloque
Throttle, un bloque acumulador denominado e\_Acum y
dos bloques QT GUI Time Sink para visualizar simultá
neamente las señales de entrada y salida.

\begin{itemize}
    \item \textbf{Vector Source:} Funciona como el generador de señales de entrada al sistema. Modela un flujo de datos discreto a partir del vector periódico \texttt{[1, 1, 1, -1, -1, -1]} habilitado con la opción \textit{Repeat: Yes}. Esto produce una onda cuadrada simétrica que alterna entre valores lógicos de $+1$ y $-1$.
    \item \textbf{e\_Acum (Bloque Acumulador):} Es el módulo programado en Python que implementa la función de integración discreta en el tiempo mediante la ecuación de diferencias:
    \begin{equation*}
        y[n] = y[n-1] + x[n]
    \end{equation*}
    El algoritmo mantiene una variable interna que acumula el valor de las muestras entrantes $x[n]$. Al recibir valores de $+1$, la salida $y[n]$ se incrementa linealmente formando una rampa ascendente; al recibir valores de $-1$, la salida se decrementa generando una rampa descendente.
    \item \textbf{Throttle:} Actúa como limitador de velocidad del flujo de muestras en la CPU. Restringe la tasa de procesamiento a la frecuencia especificada por la variable \texttt{samp\_rate} ($32\text{ kHz}$), asegurando una simulación coherente con el tiempo real.
    \item \textbf{QT GUI Time Sink (Entrada):} Visualizador osciloscópico conectado a la salida directa del \textit{Vector Source}. Permite observar la señal de entrada cuadrada en el dominio del tiempo.
    \item \textbf{QT GUI Time Sink (Salida):} Visualizador conectado a la salida del bloque \textit{e\_Acum}. Muestra la señal procesada tras el proceso de acumulación.
\end{itemize}

\subsection*{Conclusión del Bloque Acumulador}
La respuesta obtenida en la simulación confirma que el bloque \texttt{e\_Acum} se comporta de manera equivalente a un \textbf{integrador discreto en el tiempo}. Como se observa al comparar las gráficas, el procesamiento de la onda cuadrada alternada entre $+1$ y $-1$ genera a la salida una onda triangular acotada en el rango $[0, 3]$. La acumulación sucesiva de tres muestras positivas consecutivas eleva el nivel de la señal desde $0$ hasta su valor pico de $3$, mientras que la llegada de tres muestras negativas produce la pendiente descendente hasta retornar a $0$. Esto valida matemáticamente la correcta integración recursiva del algoritmo desarrollado en Python para el procesamiento de señales en tiempo real.

\subsection{Bloque Diferenciador}

Para validar el comportamiento del bloque diferenciador en GNU Radio, se diseñó un esquema de simulación enfocado en el análisis de señales analógicas. Como señal de prueba se empleo una señal cosenoidal con una frecuencia fundamental de 1kHz y una frecuencia de muestreo de 32k.

El flujo de trabajo implementado consta de los siguientes bloques principales: 

\begin{itemize}
    \item Signal Source: Genera la señal de prueba cosenoidal de referencia con amplitud unitaria.
    \item Throttle: Controla la tasa de consumo de muestras para adecuar la simulación a la velocidad de procesamiento en tiempo real sin sobrecargar el procesador.
    \item e\_Diferenciador: Bloque personalizado encargado de calcular la derivada numérica de la señal de entrada mediante operaciones discretas en el dominio temporal.
    \item QT GUI Time Sink: Osciloscopio virtual configurado con dos canales (entrada en azul y salida diferenciada en rojo) y una ventana optimizada a $128$ puntos para facilitar la visualización detallada de los ciclos.
\end{itemize}

En la simulación se comprueba que, ante los cruces por cero de la señal azul, la salida roja alcanza sus valores pico con la inversión de polaridad esperada para una diferenciación de primer orden. Escalamiento de Amplitud: La amplitud de la onda resultante muestra una reducción controlada por la ganancia discreta del algoritmo y la frecuencia de la señal, reflejando el comportamiento típico de un sistema diferenciador.

\subsection{Analizador Estadístico}

Es un \textbf{Embedded Python Block} (bloque embebido en Python) de GNU Radio, implementado como una subclase de \texttt{gr.sync\_block}. Recibe una entrada (la señal) y produce cinco salidas simultáneas, cada una con una estadística calculada de forma acumulativa desde el inicio de la simulación:

GNU Radio no procesa la señal muestra por muestra, sino en bloques (buffers) de tamaño variable $N$, cada vez que se invoca el método work(). Como las estadísticas deben ser acumulativas es decir, deben considerar todas las muestras procesadas desde el arranque y no solo el bloque actual, el código guarda el estado entre llamadas mediante variables de instancia inicializadas en el constructor. Sin esta persistencia, cada llamada a work() reiniciarí́a el cálculo desde cero y el resultado no representaría el promedio real de toda la señal procesada.

\subsubsection*{Fórmulas de cálculo}

Cada salida del bloque corresponde a una estadística distinta, calculada según las expresiones mostradas en la Tabla~\ref{tab:formulas}.

\begin{table}[h]

\caption{Fórmulas de cálculo de cada estadística}
\label{tab:formulas}
\begin{tabular}{|l|c|}
\hline
\textbf{Estadística} & \textbf{Fórmula} \\
\hline
Media & $\displaystyle \bar{x}[n] = \frac{1}{n}\sum_{k=1}^{n} x[k]$ \\
\hline
Media Cuadrática & $\displaystyle \overline{x^2}[n] = \frac{1}{n}\sum_{k=1}^{n} x[k]^2$ \\

\end{tabular}
\end{table}

\section{Conclusiones}

\begin{itemize}
    \item Se comprobó que el bloque acumulador \texttt{e\_Acum} actúa como un integrador discreto, transformando la señal cuadrada de entrada $[1,1,1,-1,-1,-1]$ en una salida tipo rampa/triangular acotada en $[0,3]$, evidenciando su naturaleza recursiva y validando la ecuación $y[n] = y[n-1] + x[n]$.

    \item Se verificó que el bloque diferenciador \texttt{e\_Diferenciador} identifica con precisión los flancos y transiciones de una señal cosenoidal, generando picos de magnitud proporcional al cambio de nivel e invirtiendo la polaridad en los cruces por cero, validando así la ecuación $y[n] = x[n] - x[n-1]$.

    \item El analizador estadístico calculó correctamente las cinco métricas (Media, Media Cuadrática, RMS, Potencia Promedio y Desviación Estándar) en tiempo real, con resultados prácticamente idénticos a los valores teóricos para el vector de prueba $(1,2,-1)$, confirmando que estas métricas dependen de los valores de la señal y no de la velocidad de procesamiento ni de la tasa de muestreo.

    \item Se determinó que la precisión de la media es sensible al número de muestras acumuladas, mientras que los cambios en la energía de la señal se reflejan de forma más inmediata en el valor RMS, validando la sensibilidad de este último para la caracterización de señales estocásticas.

    \item El uso correcto de variables de instancia para preservar el estado entre llamadas al método \texttt{work()} resultó indispensable, dado que GNU Radio procesa la señal por bloques (buffers) de muestras y no de forma continua.

    \item La implementación de estas métricas en tiempo real resulta aplicable en escenarios reales de procesamiento de audio, como la detección de desplazamientos DC mediante la media o la medición de sonoridad percibida (\textit{loudness}) a través del RMS, parámetros útiles para la optimización de mezcla y diseño de compresores.

\end{itemize}
